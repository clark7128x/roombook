# Результати перевірки RoomBook

06.11.2026. Серверна реалізація і локальні експлуатаційні сценарії перевірені. **Загальне приймання T-29/T-30 не підтверджене:** є виміряні відхилення продуктивності, неповне зіставлення ID, частково виконаний браузерний чекліст та зовнішні перевірки, для яких не задано production-середовище.

## Автоматичні перевірки

- Фінальний повний `mvn test`: **339 тестів у UTC та 339 в America/Los_Angeles**, без помилок і пропусків. `target/t30-full.log`, 05:10 хв.
- Після уточнення текстів двох шаблонів: 11 UI/сіткових тестів у кожній зоні, без помилок і пропусків (`target/t30-ui-final.log`). Фінальний контейнер зібраний повторно й перевірений у браузері.
- 13 архітектурних перевірок у кожній зоні: прибрано всі `allowEmptyShould(true)`, відсутні/порожні шаблони не проходять. AR-08 виправлено на правильну позитивну вибірку класів із заборонною умовою; негативна фікстура доводить відхилення прямого читання часу.
- Реальні HTTP/сесії/CSRF, актуальні ролі й enablement, API та Thymeleaf/HTMX-контракти, часові межі, PostgreSQL constraints/права, 50-потокова конкуренція й аудит після сценаріїв входять у цей набір.
- HTML сітки: 102 543 байти для 20 кімнат і 250 458 для 50, однаково в обох зонах; тест обмежує результат 300 000 байт.
- Python: два тести backup retention/monitor rules і тест ранньої відмови ключа пройшли. Відсутній ключ зберігає `lastSuccess` і виставляє `lastResult=failed`.
- [Індекс доказів](coverage-evidence.md): 316 зареєстрованих ID, 95 без Java-тегу. Це відкрита умова T-30, а не прихований успіх. FR-24 вилучено як явно відхилену вимогу Q-04; A-66…A-72 додано з етапу 9.

## Версії та межі

JDK збірки 21.0.12.1+1, Maven 3.10.0, Spring Boot 4.1.2, Spring Framework 7.0.10, Spring Security 7.1.2, Hibernate 7.4.13.Final, Jackson 3.1.7, Flyway 12.4.0, Testcontainers 2.0.5, ArchUnit 1.4.0, PostgreSQL 16, локальний HTMX 2.0.4. Runtime контейнера — digest-pinned Temurin 21.0.13+9. Точні image ID в окремих звітах стосуються саме виміряних збірок.

Повний [реєстр ризиків і чекліст запуску](acceptance-risks.md) відділяє підтверджене від неперевіреного: TLS/HSTS, office/VPN, off-host storage, NTP, доставка сповіщень, ротація журналів і відповіді власника потребують реального середовища. Віддалений GitHub CI не запускався, production-деплой не виконувався, затвердження T-31 від 01.11.2026 зафіксовано в актуальному README макетів.

Порядок запуску, резервування, відновлення й відкату — у [runbook](runbook.md). Початкові результати T-01 зберігаються в історії Git; наведений звіт відображає подальші перевірки T-17…T-30.
