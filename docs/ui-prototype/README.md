# Переговорні: статичні UI-макети (версія 2)

Статичні HTML і CSS усіх екранів сервісу бронювання переговорних кімнат за `09-ui-design.md`: 19 сторінок, п’ять CSS-файлів, `icons.svg` і шрифти. Це задача T-31 і еталон вигляду для виконавця (Claude Code): шаблони й `static/` будуються за ним. Каталог лежить у `docs/ui-prototype/` і під час реалізації не редагується, зміни вигляду йдуть через архітектора. Бекенда немає: авторизація, пошук, створення й скасування бронювань не працюють, сторінки лише посилаються одна на одну.

Файли кроку 0 (стилі й іконки) та `components.html` були відновлені за `09-ui-design.md`, бо їх не збережено з першого кроку. Усі класи з HTML у CSS визначені.

## Як переглядати

Відкривайте макети через локальний сервер. У каталозі макетів виконайте `python -m http.server 8000` і відкрийте `http://localhost:8000/occupancy.html`. Chrome не завантажує зовнішній `<use>` з `file://`, тому при відкритті файлу подвійним кліком усе працює, окрім іконок у повідомленнях. Через HTTP іконки вантажаться.

## Відхилення від 09-ui-design.md

1. У `occupancy.html` 8 кімнат замість 20 (ліміт довжини відповіді при генерації).
2. Посилання на вільні слоти є лише в стовпці першої кімнати.
3. Атрибутів `hx-*` у макетах немає.
4. Додано `components.html` і окремі файли станів.
5. Панель `#room-day` у формі бронювання має модифікатор `tl-single`: без посилання «Забронювати» й з нижчою шапкою кімнати.

## Що змінено після огляду

- Обгортка сітки `tl-scroll` має ширину за вмістом: зникла біла порожня смуга праворуч від сітки й порожня біла плашка в панелі кімнати.
- У панелі `#room-day` прибрано зайве посилання «Забронювати».
- Повідомлення мають ширину форми (520 px), а не 70 символів.
- Заголовок сторінки й вкладки обмежені шириною таблиці (1100 px), кнопка «Додати кімнату» стоїть над краєм таблиці.
- Дії в рядках таблиць (синя й червона) мають вагу 400 замість 500, щоб стовпець червоних дій не домінував.
- Орфографія: «конференц-зв’язок».
- Додано шрифти й `OFL.txt`.
